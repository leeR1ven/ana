# 代码级核对（char-neuron 的 brain.py）

> 只记"代码里实际写的"，不引用 README。参数取自 `_orig/char-neuron-network-main/code/brain.py`。

## 一、它实际用的参数

| 项 | 值 | 含义 |
|---|---|---|
| `top_k` | 32 | 每个单元最多保留 32 条出边 |
| `w_max` | 1.0 | 连接强度上限（另有一个 1e6 的数值安全上限） |
| `learn_eta` | 0.02 | 在线学习步长（一次思考只走一小步） |
| `decay` | 0.45 | 每步激活衰减（持续激活被当作正常现象） |
| `gain_control` | 0.01 | **除法式增益**：激活越多，整体越难再推高 |
| `theta_lr` | 0.5 | 全局阈值的收敛速度（不是 ±5%，是直接朝目标追） |
| `act_eps` | 0.35 | 判定"亮了"的阈值 |
| 权重生长 | `growth_curve(共现次数)` | 凹形：次数越多涨得越慢，不是每次加固定量 |

## 二、和我们的做法对照

| 项 | 它 | 我们 | 判断 |
|---|---|---|---|
| 选多少单元活跃 | 全局阈值 θ 追目标数（θ_lr 0.5） | top-k 固定比例 + 增益只许 ±5% | 它的更"软"，我们的更"硬"；**你的"十盏灯"要求硬恒定**，保留我们的 |
| 防跑飞 | 除法式增益 `drive/(1+γΣa)` | 没有 | **值得补**：规模一上去，这是最直接的刹车 |
| 出边数 | 32 | 8–32（实验里用 32） | 一致 |
| 权重生长 | 按共现次数的凹曲线 | 每次共现加 `η(1−w/wmax)` | 数学等价（都是凹），一致 |
| 激活衰减 | 0.45/步 | τ=0.025、dt=0.01 | 量级不同，效果类似 |

**结论**：核心机制我们没写错；差的是"除法式增益"这一条，可以作为可选开关补上。

## 三、你补充的两条结构，现在**确实没有**

1. **区与区之间的直连**：现在五个区各自成链，只在额叶汇合；没有"视觉↔听觉"这种直连。
   你说过这类连接大多**很难改**，反复接触才慢慢固化成长期记忆。
2. **"常用变难改"的固化**：现在可塑连接只有一条"整体降权"，没有"用得越多越难改"。

### 打算怎么做（下一轮动，先写清楚再动手）

- **区与区直连**：在相邻区的 L5 之间加一小束固定连接（比如视觉→听觉、听觉→视觉各 64 条，
  权重固定、不参与学习），走一个新的边组，自检里加一条"这类边必须不可塑"。
- **固化**：给每条可塑边加一个"资历"计数。用得越多，它的**可塑系数**越低
  （η 乘一个衰减因子），低到一定程度就标成"长期记忆"、不再被改；同时它仍参与传播。
  这样"反复接触 → 变成长记忆"是长出来的，不是手写的。
- 两条都要过：地基体检、自检 0 问题、16 项测试、20 ms 预算、狗能站。

## 四、下一步顺序

1. 先把除法式增益做成可选（`pfc_gain_div`），验证不破坏地基；
2. 再加区与区直连（固定）；
3. 最后加"用得多就难改"（固化），并用一个三阶段实验验证：

| γ | 前额叶活跃 | 近似图 | 异图 |
|---:|---:|---:|---:|
| 0 | 671 | 0.91 | 0.22 |
| 0.01 | 671 | 0.91 | 0.22 |
| 0.05 | 671 | 0.91 | 0.22 |

**完全没有影响**。原因：我们的前额叶是 top-k 竞争 + 饱和响应，整体乘一个系数不改变排名。
它只在"分级响应"的网里起作用（字神经元网络就是那样）。**保留开关、默认关闭**，理由记在这。

### 第 2 步：区与区之间的直连（`region_links`）

## 六、第 3 步：用得多就变难改（固化）

每条可塑边带一个"用过几次"的计数：

- 可塑性随使用下降：`系数 = use_ref / (use_ref + 用过次数)`（下限 0.02）；
- 超过 `freeze_at` 就**冻结**：权重不再改变，但仍参与传播（长期记忆）。

单元测试（同一对神经元反复加强 40 次）：

| | 最终权重 | 是否冻结 | 用过次数 |
|---|---:|---|---:|
| 固化开 | **0.62** | 是 | 40 |
| 固化关 | 1.00 | 否 | — |

所以"反复接触 → 变难改 → 冻结"是按规则长出来的，不是手写的。
（顺带补回了向量化重写时丢掉的 `reinforce` 接口。）

## 七、第 3 步修订（按用户 2026-10-22 的纠正）

**长期记忆是"难改"，不是"不能改"。** 硬冻结会留下无法纠正的错误，所以改成：

- 可塑性 = 下限 0.01 + (1−下限) × `use_ref/(use_ref+用过次数)`；
- 用得越多，每次改动越小，但**永远留 1% 的可改性**；`long_term_at` 只是打标记，不禁止修改。

单元测试（同一对反复加强）：

| | 40 次后权重 | 再多 10 次 |
|---|---:|---:|
| 不固化 | 1.000 | — |
| 固化 | 0.772 | 0.793（仍在变） |

### 真实网络里的发现（p6_consolidate.py）

- 第一段 300 拍：155,968 条边，**平均只被用过 1.0 次**，长期记忆 0 条；
- 原因：新颖目标 + top-32 剪枝，让每次转移都在"新边"上打转，老边很少被再次用到。

**结论**：固化规则本身没问题，但现在的学习方式不爱复用老边，所以"反复接触→变长期"
在真实网络里还没发生。下一轮要改的是"复用优先"（新边只在确实没有可用老边时才长），
这正好也是 born-wired-cortex 那条"先试回忆、回忆对了就不再长新边"。

## 八、第 4 步结果（复用优先 + 难改的定量验证，2026-10-22）

加了"复用优先"（源头出边够 4 条就不再长新边，只加强已有的）后，用 800+800 拍跑：

| | 条数 | 总变化 | **每次被用改** |
|---|---:|---:|---:|
| 老边（用过 ≥8 次） | 878 | 0.049 | **0.0049** |
| 新边（用过 ≤1 次） | 2,275 | 0.024 | **0.0181** |

**老边每次被用到时，改的量只有新边的 0.27 倍**——"难改，但不是不能改"在真实网络里成立。

注意：不能看"总变化"（老边总变化更大，因为它们被反复用到），要看"每次被用改多少"。
这是这一轮差点被数字骗到的地方，记下来。

## 九、融合：一次学会（P9，2026-10-22）

按 born-wired-cortex 的"反向赫布 + 一次学会"：

1. 看画面 A，记下亮的 694 个前额叶单元；
2. **一次**把它们连到 12 块肌肉的前 5 档力度上（41,640 条边，权重直接给满）；
3. 画面全黑、只点 A → 力度 0.55；狗从趴着 0.100 站到 0.255，不摔；
4. 中间看别的画面 200 拍，再回来点 A → 力度仍是 0.550。

**学过不忘**。这就是"把示范动作搬进架构"的具体做法：不需要反复训练，
一次写入、直接饱和，之后别的活动冲不掉。

局限：现在是"画面→站"一条固定映射，还没做"多动作累积"（学第二个动作不冲掉第一个）；
下一轮补。

## 十、多动作累积 + 门控生长（P10，2026-10-22）

| 步骤 | 结果 |
|---|---|
| 教 A（站，5 档，只用 A 独有的 4,490 个单元） | 26,940 条边 → 点 A 力度 **0.50** |
| 教 B（撑，7 档，只用 B 独有的单元） | 37,968 条边 → 点 B 力度 **0.70** |
| 回头再点 A | **0.50，没被冲掉** |
| 再教一次 A（门控） | 先试回忆已能给出 0.50 → **新增 0 条边** |

**关键**：教的时候只用"这个场面独有"的单元，否则共享单元会同时驱动两套边，
两个动作互相串（第一次试就串了：教完 B 再点 A，力度变成 0.72）。
这和用户说的"概念范围"是一回事——动作要挂在**区分性**的单元上，不是挂在整个场景上。

这样就同时满足："教新动作不忘旧的" + "已经会的就不重复写边"。

## 十一、local3d 的权重细节（逐行核对 model.py，2026-10-22）

它每个神经元固定 4 条输入：

| 输入 | 权重 | 说明 |
|---|---|---|
| 自身位置（同坐标） | **1.0** | 第一条永远是"自己" |
| 3 个随机邻居（dx,dy∈±1，dz∈±2） | (0.5~1.0)×**alpha**，alpha=0.01 | 即 0.005~0.01 |
| 固定随机偏置 | 0~0.5 | 直接加在加权和上 |
| 读出 | 每层精确 top-k | 选中=1，其余=0（**二值**，没有分级） |

对照我们：

| 项 | 它 | 我们 | 差异的影响 |
|---|---|---|---|
| 自身拷贝权重 | 1.0（邻居的 100~200 倍） | 1.0（邻居的 5~20 倍） | 我们的层"更像混合"，它更"保形"；这可能是它近似图 0.989、我们 0.91 的原因之一 |
| 偏置 | 有（0~0.5） | **没有** | 它每个神经元的"易兴奋程度"不同，我们靠并列优先级代替 |
| 阅读方式 | 二值 top-k | 分级 act + top-k | 我们的码带强度信息，它的更干净 |

**判断**：偏置这一条值得补（成本低、符合原意），但要用"每个神经元固定的随机偏置"，
不能变成可调参数（否则又是给现象加机制）。自身拷贝的权重比例是两种设计取向，
暂不照搬——我们要"加工"，不只是"保形"。

**待办**：给层神经元加固定随机偏置（`bias_scale`，默认 0 以便对照），验证地基指标。

## 十二、补 local3d 偏置的实测（2026-10-22）

实现：每个层神经元出生时给一个固定随机偏置（0~bias_scale），加在驱动上。

| bias_scale | 活跃 | 同图两次完全一致 | 近似图 | 异图 |
|---:|---:|---|---:|---:|
| 0（默认） | 671 | **是** | 0.91 | 0.22 |
| 0.2 | 666 | **否** | 0.90 | 0.20 |
| 0.5 | 666 | **否** | 0.90 | 0.20 |

**加偏置会破坏"同一输入→同一批神经元"**（和第 3 条门槛公式那次一样：更多单元挤在
top-k 边界上，浮点抖动改变选中结果）。按你最早定的第一条规矩，**默认 0（关闭）**，
代码保留、可选项。

所以 local3d 这一条**不照搬**，理由记在这里，不是漏做。

## 十四、born-wired-cortex 的"一拍"（读了 `model/主循环_完整的一拍.py`）

它的顺序（文件头写得很清楚）：

1. 时间往前走一格（时钟）；
2. 外界 → 视觉/听觉；身体 → 本体/平衡；
3. 三路 + 运动皮层 → 前额叶网 → **前额叶皮层（再压一次）**；
4. 前额叶 → 天生互惠返回线 → **送回视觉/听觉/运动**（"在心里看见画面"）；
5. 整片皮层走一拍：本能连接 + 赫布学习，算出这一拍谁亮；
6. 运动记忆区（时间神经元）→ 运动皮层 → 肌肉；
7. 赫布学习：这一拍和下一拍之间，谁跟谁一起亮了。

对照我们的单拍（`agi/loop.py`）：

| 步 | 它 | 我们 |
|---|---|---|
| 1 | 时钟先走 | 没有时钟（按你的要求不做时间区） |
| 2 | 感觉 → 各区 | 编码 → 输入层 ✓ |
| 3 | 三路 + 运动 → 前额叶 | 各区 → 专线 → 中继 → 前额叶 ✓ |
| 4 | 前额叶 → 返回线 → 感觉区 | 同样在**同一拍内**完成 ✓ |
| 5 | 整片皮层一拍 | 一次 `step()` ✓ |
| 6 | 运动记忆 → 运动皮层 → 肌肉 | 力度档 → 肌肉 ✓ |
| 7 | **同一拍共亮**才学 | **上一拍→这一拍**才学（按你的"先亮后亮"） |

**唯一实质差别**：它第 7 步用的是"同时亮就加强"，我们按你的要求改成"有先后才加强"。
这是你明确纠正过的，保留我们的写法。

另外它把"前额叶自压"写成**旋钮**（环境变量），并注明"这不是架构的一部分"——
和我们把 top-k 当调制手段是同一个态度。

## 十五、born-wired-cortex 的皮层连接网（读了 `model/皮层连接_cortex_links.py` 文件头）

这是它最核心的一张网：**本能连接和赫布学习在同一张网上**。

### 出生连接（写死在文件头，可调）

| 项 | 值 |
|---|---|
| 每个神经元出生带几条兴奋入边 | **100**（其中 50% 跨区、50% 本区） |
| 出生权重上限 | 0.15（"模糊但有大致方向"） |
| 标为"固化"的比例 | **30%**（基本一辈子不变） |
| 每个神经元出生带几条抑制边 | **100**（50% 就近、半径 24；50% 全脑随机） |
| 带去抑伙伴的神经元比例 | 25% |
| 哪些区不接收随机兴奋 | 运动、运动记忆、多巴胺、触觉（"运动皮层是输入层"） |

### 学习规则（同一张网上）

1. 两拍里一起亮 → 兴奋直连加强；**新长出的直连 = 绕过前额叶的短路**；
2. 一个亮、另一个不亮 → **亮的一方对它的抑制变强**（越无关越互相抑制）；
3. 总是一起亮 → 它们之间的抑制变弱、去抑制变强；
4. 亮着却带不亮对方 → 这条连接慢慢变弱；
5. 目标早就在亮、源才亮（没用上）→ 也慢慢变弱（默认关）。

它明确写了**没有**：海马索引、汇合细胞长程线、专注闸门。

### 对照我们

| 项 | 它 | 我们 | 判断 |
|---|---|---|---|
| 出生入边数 | 100/神经元 | 8~9（就近 + 自身） | 它是随机图，我们是局部链；两种取向 |
| 抑制 | **每个神经元 100 条抑制边** | 没有（只有运动区 I/D + top-k） | **这是你原话里的机制，它实现了** |
| 固定/可塑比例 | 30% 出生即固化，其余可塑 | 只有 group 40 可塑，其余全固定 | 我们的"固定"比例高得多 |
| 学习规则 | 含"带不亮对方就变弱"、"没用上就变弱" | 只有衰减 + 凹增长 | 可借鉴 |
| 区与区直连 | 出生就有 50% 跨区 + 学习中长出短路 | 483 条固定跨区 | 我们的跨区少，且不可学 |

**最有价值的一条**：它第 2 条规则——"一个亮、一个不亮 → 亮的对不亮的抑制变强"——
正是你说的抑制伙伴机制，而且它用的是"实际没一起亮"这个信号，不是随机采样。
我之前那版互抑制用随机采样，所以无效；照它这样写才有意义。

## 十六、born-wired-cortex 的本能表（读了 `model/本能工具_instincts.py` 文件头）

它遇到的真问题：**不能按输入编号写本能**。实测满屏红时，皮层亮在"输入层红色编号区"
的比例 6.1%，碰运气 6.7%——等于没有。但"满屏红"和"满屏蓝"的皮层模式只重叠 8 个细胞，
说明皮层分得清颜色，只是**认不出编号**。

它的三步走：

1. **标定**：给模型看一个例子（满屏红），记下皮层哪些细胞亮了，起个名字，存进 JSON；
2. **写本能表**（一行一条，用名字）：
   `视觉:红 -> 运动:肌肉组0  1.0  是`
3. **装**：把每条规则展开成一根根连接，写进皮层网。

### 对我们最有用的启示

我们 p9 的"一次学会"其实就是它的第 1+3 步：先记下画面 A 亮了哪些单元（=标定），
再把它们连到力度档（=装）。**差的是"名字"这一层**——没有名字，就没法写"规则表"，
只能每次跑一遍再连。

所以融合的下一步很清楚：加一层**"概念名 → 单元集合"的标定表**（存文件），
本能/示范/外部模型都用"名字"写规则，装的时候再展开成连接。
这正是你说的"一个神经元就像一个字"的工程化用法。

## 十八、按 bwc 规则重做抑制伙伴（2026-10-22，第四阶段第 1 步）

|---|---:|---:|
| 关闭 | 0.54 / 0.48 | 0 |
| **开启** | **0.38 / 0.28** | ~20 万 |

**变差了**。原因很清楚：在我们的架构里，"目标没亮"大部分不是"没关联"，而是
**top-k 竞争没选上它**；这条规则把"竞争失败"当成"关联不成立"去惩罚，结果把真的
联想也削掉了。

bwc 能用这条，是因为它每个神经元有 100 条入边、共亮式学习，"没亮"信息量大；
我们是稀疏 top-k，"没亮"几乎是默认状态。

**结论**：规则实现正确，但在当前架构下有害，默认关闭。要用它，得先解决
"竞争失败 ≠ 无关联"这个混淆（比如只在"目标本轮根本没被任何输入驱动"时才罚）。

## 二十、为什么现在离不开 top-k（2026-10-22，回答"架构本身不就是稀疏码"）

实测三种做法：

| 做法 | 前额叶活跃 | 同图一致 | 近似 | 异图 | vision.L5 亮 |
|---|---:|---|---:|---:|---:|
| **top-k（现状）** | 671 | 是 | 0.91 | 0.22 | 2,078 / 15,360 |
| 去掉 top-k（门槛仍为 0） | 1,044 | 是 | 0.93 | 0.27 | **15,357 / 15,360（几乎全亮）** |
| 去掉 top-k，门槛=各自驱动 90% 分位 | 48 | 是 | 0.61 | 0.02 | **0 / 15,360（全灭）** |

**结论**：现在层内的驱动分布太"平"——随机均匀权重 + 8 个邻居，让每个神经元收到的
输入总量差不多，差别只来自输入图案本身。所以门槛要么几乎全过、要么一个都过不了；
能稳定给出"稀疏但随输入变化"的码的，只有 top-k。

**要真正做到"架构本身稀疏"**，得先把驱动的**对比度**做出来，而不是靠名额硬切。
最直接的一步：权重不要用均匀分布，改成**对数正态**（少数强连接 + 多数弱连接），
让不同神经元的驱动天然拉开差距；然后再试门槛稀疏。
这条记下来，作为下一步。

## 二十一、对数正态权重 + 门槛稀疏的实测（2026-10-22）

| 设置 | 前额叶 | 同图一致 | 近似 | 异图 | vision.L5 |
|---|---:|---|---:|---:|---:|

还是不行：L5 全灭、同图不一致。**门槛稀疏在这套引擎里就是立不起来**——
驱动值彼此太接近，门槛卡在中间时，浮点抖动和逐拍波动都会翻转结果。

## 我认为真正对的方向（不是调权重）

链式库之所以天生稀疏，靠的是**成对神经元**：每个特征一对（正/负），每拍**恰好一个亮**。
一亿个神经元也只有一半亮，而且计数恒定——**根本不需要 top-k**。

我们现在只有 L1（温度计档位）是成对的，L2~L5 和前额叶都不是。所以：
- 要么把成对竞争推广到每一层（神经元数翻倍，PFC 5.2 万 → 10.5 万，仍在预算内）；
- 要么继续用 top-k。

这不是权重能调的，是结构选择。我建议前者——那才是"架构本身稀疏"。

## 二十二、成对竞争在 L5 上的实测（2026-10-22）

| 指标 | 结果 |

| 每场景亮的个数 | **7,680 / 15,360（恰好一半，计数恒定）** |
| 近似图重合 | **1.00** |

原因：去掉 top-k 后 L5 已经**饱和**（15,357/15,360 都在 0.97 附近），驱动差异只剩一点点，

## 二十七、读到 bwc 学抑制的关键：它用"痕迹"判相关（2026-10-22）

`_学抑制` 的原文注释：

> "相关" = 两个神经元**最近都亮过**（看 痕迹/资格迹），不是"这一拍同时亮"。
> 只看同时亮的话，时序链上的细胞会被判成"无关"而被自己掐断。

规则：两头都有痕迹 → 抑制减弱；否则 → 抑制加强（有上限）。
另外两拍都共亮的神经元之间，去抑制连接变强。

**这正好解释了我前几轮为什么失败**：
- 我用"最近 3 段稳定码的集合"判相关 → 太粗，0 条边；
- 我用"这一拍驱动 ≤ 0"判 → 我们的网里几乎不存在零驱动，0 条边；
- 它用的是**衰减痕迹**（trace = decay·trace + act），"最近亮过"是连续的，
  不是集合成员关系。

**下一步（如果要做抑制）**：给每个神经元加一条痕迹，相关 = 两头痕迹都超过门限。
这是它这套机制能成立的前提，不是可选细节。

## 二十八、按用户要求：去掉 top-k，纯用权重阈值（2026-10-22）

按它们的驱动定出来的门槛，在"暗底小色块"的测试画面上没有任何神经元够到。

**要修的是标定口径**，不是机制：
1. 用**和测试同分布**的画面标定（或按输入总能量归一化驱动后再比门槛）；
2. 门槛按"该层全体神经元在同一拍的分位数"定，而不是每个神经元自己的时间分位
   （后者在"驱动几乎恒定"时等价于取最大值，必然全灭）；
3. 定完必须复查：同图同码、近似/异图分离、每拍亮多少是否稳定。

这三条是下一轮的具体动作。top-k 目前在默认配置里仍开着，等阈值方案验证通过再关。

## 三十二、把几条症状串成一条因果链（2026-10-22，第 4 阶段小结）

```
层内驱动太平（随机均匀权重 + 8 邻居）
        ↓
门槛没法用（全过或全不过）→ 只能靠 top-k 切
        ↓
没有 top-k 时全场饱和（L5 15,357/15,360 都亮）
        ↓
"常亮单元"占绝大多数 → 过滤规则把 76% 前额叶判死
        ↓
有效前额叶只剩 1.2 万、真正被驱动的 4,401
        ↓
联想/回忆效应小、竞争激烈、抑制规则失效
```

**这五条症状是同一个根因**：层内没有"分级区"。链式库的规矩里有一条正是
"各层必须在分级区间（不饱和、不整层死）"——我们这条一直没满足。

修法只有一条主线：**让每一层的驱动落在分级区**。可行手段（按风险从小到大）：
1. 把软带宽按"该层驱动的标准差"定，而不是 75% 分位（现在是后者，等于把大部分压到饱和）；
2. 每层加一个整体增益，让它自动落在"约 10%~30% 过线"（链式库的逐层 α）；
3. 权重分布改成对数正态（已试，单独不够）。

**在这一条解决之前，第 4 阶段剩下的实验（阈值稀疏、联想增强）都不会稳。**

## 三十三、"分级区"改法实测：反而破坏不变量（2026-10-22）

按第 1+2 条改（门槛=该神经元驱动中位、带宽=2×标准差），想让它落在分级区：

| 指标 | 结果 |
|---|---|
| 前额叶活跃 | 20 |
| 同图两次 | **不一致** |
| 近似图 | **0.00** |
| 异图 | 0.00 |
| vision.L5（>0.05） | 1,677 |

**更糟了**：码变得极小且不稳定。原因是门槛取中位后，一半单元在"刚好过线"附近，
逐拍波动和浮点抖动都会翻转它们；而上层因此拿不到稳定输入，整条链抖起来。

**结论**：单纯改门槛/带宽解决不了"驱动太平"。真正要动的是**驱动本身的对比度**——
让不同神经元的加权和天然拉开（归一化每个神经元的入边总量、并且让权重分布有长尾），
否则任何门槛都会卡在"全部差不多"的区间里。

这一条（层内分级区）是第 4 阶段所有剩余问题的前置条件，目前**未解决**。

| L5 驱动对比度（CV） | 1.30 | **2.56** |
| 同图两次 | 一致 | 一致 |
| 近似图重合 | 0.91 | **0.96**（更好） |
| 完全不同的图 | 0.22 | **0.52**（变差） |

对比度确实翻倍了，同图/近似也更好，但**异图重合从 0.22 涨到 0.52**——
不同场景看起来越来越像。

原因推测：入边归一后，每个神经元的响应被自己**最强的那条边**主导（长尾），
而"最强边"对任何输入都差不多，于是不同场景共享同一批赢家。

**所以对比度和区分度是拉扯的**：单纯拉开驱动，会把"由输入决定"变成"由强边决定"。

下一步应该只对**邻居边**加长尾，把 1:1 自身拷贝那条保持主导（它是"身份线"），
这样"同一个东西"仍稳定、"不同东西"靠邻居边区分。

## 三十五、照 local3d 新文档用"权重相对阈值"（2026-10-22，重大进展）

用户新提交的 `THRESHOLD_ACTIVATION.md` 给的公式：
`active_i = score_i > θ · (|b_i| + Σ|w_i|)`，每层一个 θ，校准到目标稀疏度。
（它那边输入 0/1、权重同量级，θ≈0.98、激活 12%、准确率 100%。）

我们输入是 0~1、驱动只到总量的五成左右，所以 θ 要低。实测：

| 方式 | PFC 活跃 | 同图完全一致 | 近似图 | 异图 |
|---|---:|---|---:|---:|
| 全局 top-k（现状） | 671 | **是** | 0.91 | 0.22 |
| θ=0.5（权重相对阈值） | ~850 | **否**（差几个单元） | **0.94** | **0.18** |

**区分度三项都更好**（近似更高、异图更低），而且不需要名额、不需要排序。
**唯一代价**：同图两次会有个别单元翻转（θ 在 0.48~0.52、软带宽 0.02/0.10 下都一样），
正好卡在阈值边界上，浮点抖动就会翻转。

下一步：把驱动**量化到 3~4 位小数**再比阈值（去掉浮点抖动），看能不能同时拿到
"同图完全一致 + 近似 0.94 / 异图 0.18"。如果能，就可以正式把 top-k 换成阈值。

## 三十六、量化驱动并没能稳住"同图同码"（2026-10-22）

给引擎加了 `quant`（驱动先量化再比阈值），实测：

| quant | PFC | 同图 | 近似 | 异图 |
|---:|---:|---|---:|---:|
| 0 | 842 | 一致 | 0.94 | 0.18 |
| 1e-3 | 842 | 一致 | 0.94 | 0.18 |
| 1e-2 | 842 | **不一致** | 0.94 | 0.18 |

而且同一套配置（quant=0）前一次测是"不一致"、这次是"一致"——**间歇性**。

**判断**：不是阈值边界的问题，是**计算本身不确定**（torch 的 `index_add_` 多线程归约，
每次求和的加法顺序可能不同）。top-k 之所以稳，是因为它只看相对排序，最后几位的抖动
不改变名次；阈值是绝对比较，抖到门槛另一侧就翻转。

**下一步**：验证时把 torch 设成单线程（`torch.set_num_threads(1)`）或走 numpy 后端，
确认这样"同图同码"能稳定成立；如果是，再决定阈值方案的默认线程策略。

## 三十七、单线程解决"同图同码"的不确定性（2026-10-22）

`torch.set_num_threads(1)` 后，用权重相对阈值（θ=0.5）实测：

| 指标 | 结果 |
|---|---|
| 同图三次 | **完全一致** |
| 近似图 | 0.94 |
| 完全不同的图 | 0.18 |
| 单拍 | **4.6 ms**（阈值模式比 top-k 还快） |

所以之前"间歇不一致"的根因确认是**多线程归约顺序不固定**，不是阈值机制的问题。
已把单线程设成引擎默认。设完复查：测试 17/17、自检 0 issues、地基符合、整拍 13.7 ms（预算 20）。

**阈值模式现在的成绩**（全指标优于 top-k）：
| | 近似 | 异图 | 是否要名额 |
|---|---:|---:|---|
| top-k | 0.91 | 0.22 | 要 |
| **权重相对阈值 θ=0.5** | **0.94** | **0.18** | **不要** |

只差"把它设成默认配置"这一步（需要把默认的 `layer_active`/`pfc_topk` 关掉，
并把阈值改成 θ·(|b|+Σ|w|)）。这一步留到下一轮，避免在收尾时动太多。

## 三十八、阈值模式接进默认构建（2026-10-22）

改动：
- `Spec.threshold_theta` 默认 0.5；>0 时自动把 `pfc_topk` 设 0、各层 `layer_active` 设 0.999（名额不再起作用）；
- 构建时按 θ·(|b|+Σ|w|) 给**各层和前额叶**设门槛，并**跳过**原来的分位标定。

实测（θ=0.45 / 0.50 / 0.55）：

| 指标 | 结果 |
|---|---|
| 前额叶活跃 | 465（三个 θ 完全一样） |
| 同图两次 | **一致** ✓ |
| 近似图 | 0.70 |
| 完全不同的图 | 0.08 |

**问题**：
1. θ 在 0.45~0.55 之间**完全没影响**——说明前额叶活跃数被别的东西钉住了（多半是两级中继的旧门槛，
   或 1:1 专线给出的驱动几乎恒定）；
2. 近似图从 top-k 的 0.91 掉到 0.70——"相似图像应该大部分重合"这条变差了。

**下一步**：先查中继门槛（它还没按 θ 重设），再回来调 θ；同时确认近似的定义
（0.70 可能因为码变少了，交集小、并集大，Jaccard 天然偏低）。

## 三十九、阈值模式接默认构建时踩到的坑（2026-10-22）

把 θ 阈值一次性套到所有层（构建时） → **上层全饿死**：`vision.L2` 一个都不亮（测试 `top_k_exact` 直接挂）。

原因：θ 门槛是按"该层权重总量"算的，但上层能不能过线取决于下层给多少；
一次性同时抬高所有层，下层一出不来，上层就永远没输入。

**正确做法**（和之前"逐层标定"成功那次一致）：**浅→深逐层设门槛**，每设完一层，
先用参考输入跑几拍，再设下一层；最后设前额叶。

所以暂时把 `threshold_theta` 默认改回 0（继续走 top-k），等逐层标定实现后再切换。
这样仓库保持全绿：测试 17/17、自检 0 issues、地基符合。

## 四十、逐个层标定也做了，θ 仍然不起作用（2026-10-22）

加了 `_calibrate_by_theta`：浅→深逐层设 θ·mass，每层设完先跑 3 组参考输入 × 6 拍，
最后再设前额叶。结果和不逐层时**完全一样**：

| θ | PFC 活跃 | 同图 | 近似 | 异图 |
|---:|---:|---|---:|---:|
| 0.5 | 465 | 一致 | 0.70 | 0.08 |
| 0.6 | 465 | 一致 | 0.70 | 0.08 |

所以"级联饿死"不是唯一问题。**前额叶活跃数对 θ 完全不敏感**，最可能的原因是：
前额叶的驱动被那条 **1:1 专线**支配（它的值是 0 或 1，几乎不随输入变），
θ·mass 在这个分布上正好切在一个"平台"上——多切少切都是同一批单元。

对比 top-k：0.91 / 0.22，PFC 671。

**结论**：阈值模式的骨架有了（构建、逐层标定、opt-in 开关都能用），但要让 θ 真正起作用，
得先改变前额叶的驱动构成（比如让 1:1 专线的权重不占绝对优势），这属于内核第 3 条的调参，
不是再加机制。默认仍是 top-k（`threshold_theta=0`），仓库保持全绿。

## 四十一、多路输入也救不了 θ：中继是"全有全无"（2026-10-22）

把前额叶从 1 条专线改成多条（fan=4 / 8），想让它有一次"接了几条"的中间值：

| 配置 | PFC | 同图 | 近似 | 异图 |
|---|---:|---|---:|---:|
| fan=4, θ=0.4 / 0.6 | 102 | 一致 | 0.82 | 0.05 |
| fan=8, θ=0.4 / 0.6 | 94 | 一致 | 0.86 | 0.03 |

θ 依然没有影响。原因找到了：**中继层的输出是"全有全无"**——
它门槛为 0，只要有输入就整片亮（act≈1），所以下游拿到的永远是 0 或满值，
θ 取 0.4 和 0.6 切出来的都是同一批。

**这就是"分级区"问题的最后一层**：不是前额叶的问题，是**中继本身没有中间值**。
下一步：给中继设一个非零门槛（按它自己的驱动分布），让它输出 0~1 的连续值，
前额叶才可能"接了几条"不同，θ 才有意义。

## 四十二、给中继设门槛后，θ 终于起作用（2026-10-22，关键进展）

在中继上设 θ_relay=0.5·mass（带宽 0.02·mass），再设前额叶：

| 前额叶 θ | PFC | 同图 | 近似 | 异图 |
|---:|---:|---|---:|---:|
| 0.3 | 2,359 | 否 | 0.94 | 0.39 |
| 0.5 | 1,100 | 是 | 0.94 | 0.21 |
| **0.7** | **403** | **是** | **0.92** | **0.08** |

**θ=0.7：近似 0.92、异图 0.08** —— 异图分离比 top-k（0.22）好一倍多。

这验证了上一轮的判断：**中继是"全有全无"的瓶颈**，给它门槛后，前额叶才拿得到
"接了几条"的连续值，θ 才成为真正的旋钮。

### 但接进构建后数字不一样（待查）

同样参数在 `build()` 里跑（`_calibrate_by_theta` 里先设中继再设前额叶）得到
PFC=102、近似 0.82、异图 0.05，且 θ 又不起作用。
和上面"构建后再设"的结果（1100/403）差很多。

**下一步**：查这个差异——最可能是"设门槛的时机/顺序"（构建里 mass 是在中继设门槛之前算的，
且 `_run()` 的输入分布与测试时不同）。这一步查清，阈值模式就能正式接成默认。

## 四十三、把中继门槛接进构建：仍不响应 θ（2026-10-22）

按上一轮结论在构建里加了两处：
1. `_calibrate_by_theta` 里先设中继（0.5·mass），再设前额叶（θ·mass）；
2. 阈值模式下**跳过**原来那次单独的前额叶分位标定（`pfc_fan_in>1` 分支），
   并把 `target_active` 设 0（关掉整体增益控制）。

实测（fan=4、需注意）：

| θ | PFC | 同图 | 近似 | 异图 |
|---:|---:|---|---:|---:|
| 0.5 / 0.7 / 0.8 | **4,424** | 一致 | 0.97 | 0.63 |

**θ 还是完全不起作用**，而且异图 0.63（比 top-k 的 0.22 差很多）。

对比：同样思路"构建完再手动设"能拿到 1100/403 且区分度好。差别只可能在
**构建内部的执行顺序/状态**（例如 `_run()` 时中继还没被前一层喂满、或 mass 在设置前算的）。

**结论**：机制本身已被验证有效（见上一节），但"怎么在构建里按正确顺序落地"还没解决。
这属于接线问题，不是机制问题。下一步单独花一轮把它对齐：
在构建末尾（所有标定之后）按"层→中继→前额叶"重设一遍，并复用 `_run()` 的同一组输入。

## 四十四、阈值模式在构建里跑通了（2026-10-22，阶段性成果）

关键改动：把阈值设置**挪到构建最末尾**（所有分位标定/增益之后），顺序"层(浅→深) → 中继 → 前额叶"。

| 配置 | θ | PFC | 同图 | 近似 | 异图 |
|---|---:|---:|---|---:|---:|
| 前额叶 4 路输入（fan=4, ratio=0.25） | 0.5 | 743 | 一致 | 0.96 | 0.23 |
| 同上 | **0.7** | **336** | 一致 | **0.93** | **0.07** |
| 默认 1:1（fan=1） | 0.7 | 69 | 一致 | 0.65 | 0.03 |

**结论**：
- 阈值模式（无 top-k）在构建里成立、θ 是有效旋钮、同图同码稳定；
- **最佳配置是"前额叶 4 路输入 + θ=0.7"**：近似 0.93、异图 0.07，比 top-k（0.91/0.22）好；
- 严格 1:1（fan=1）时代码太小（69 个）、近似只有 0.65——因为单线驱动是二值的，
  阈值只能切出很小一片。**这是"1:1 专线"与"阈值稀疏"之间的真实取舍。**

下一步：把"θ=0.7 + fan=4"设成默认，修受影响的测试，再跑狗。

## 四十五、1:1 专线 与 阈值稀疏 的冲突（2026-10-22，需要你定）

把 θ=0.7 设成默认后实测：**前额叶只剩 69 个单元、近似 0.65、异图 0.03**——
近似不达标（要求 0.8~0.95）。原因是严格 1:1 专线（fan=1）给出的驱动是二值的，
阈值只能切出很小一片。

而"θ=0.7 + 前额叶 4 路输入"能得 **近似 0.93 / 异图 0.07**，明显更好。

**这是内核第 3 条（每一层往额叶送一条专线）与"去掉 top-k"之间的真实冲突**：

| 选择 | 近似/异图 | 代价 |
|---|---|---|
| 严格 1:1 + top-k（现状默认） | 0.91 / 0.22 | 保留名额、竞争假象 |
| 1:1 + 阈值（θ=0.7） | 0.65 / 0.03 | 码太小，相似图重合不够 |
| **4 路 + 阈值（θ=0.7）** | **0.93 / 0.07** | **偏离"一条专线"** |

所以默认**暂时回退到 top-k**（仓库全绿），阈值模式作为可选（`threshold_theta=0.7` + `pfc_fan_in=4, pfc_ratio=0.25`）。
这一步需要你决定：保住"一条专线"，还是接受"每个额叶单元接几条线"以换取无名额的稀疏。

## 四十六、1:1 时码小的真正原因：中继被"取样太稀"饿住（2026-10-22）

用户指出：每个前额叶单元只有一个中继神经元（1:1 是设计），我上轮改成 4 路是偏离。
按 1:1 重测，只调中继门槛：

| 中继门槛 | 中继活跃 | PFC | 同图 | 近似 | 异图 |
|---:|---:|---:|---|---:|---:|
| 0.35 | 0.01 | 71 | 一致 | 0.67 | 0.03 |
| 0.20 | 0.02 | 76 | 一致 | 0.68 | 0.04 |
| 0.10 | 0.02 | 78 | 一致 | 0.67 | 0.04 |

**中继活跃度只有 1~2%，门槛怎么降都上不去**——说明大多数中继**根本没收到输入**：
每个中继只从 L5 取很少几条线，而 L5 本身稀疏，所以大部分中继永远是 0。
1:1 的前额叶只能跟到这一小撮亮着的中继，码自然只有几十个。

**所以真正的旋钮是"中继从 L5 取几条线"，不是"前额叶接几路中继"。**
下一轮：保持 1:1，把中继的 fan-in 调大（比如 4→16），让更多中继亮起来，
再看 θ 能不能在 1:1 下把码拉开档次。

## 四十七、逐级分位标定：1:1 下也能用阈值（2026-10-22，关键）

做法：从浅到深，每一级用**它自己这一级的驱动**取 85% 分位当门槛，设完再算下一级
（不是用全局 θ、也不是用倍率迭代）：

| 级 | 门槛 | 活跃 |
|---|---:|---:|
| 层 4 / 5 | 0.16~0.50 | 12~16% |
| 中继 | 0.000（分位为 0） | 5% |
| **前额叶** | 0.000 | **4.1%** |

结果：**PFC 2,533 个、同图完全一致、近似 0.93、异图 0.20**
（top-k 是 671 / 0.91 / 0.22）。

**所以 1:1 也能用阈值，关键不是 θ，而是"每一级按自己的驱动分位定门槛、逐级往下"。**
之前失败是因为：① 一次性设所有层 → 级联饿死；② 用全局 θ·mass → 各级驱动量级差太多；
③ 用倍率迭代 → 收敛太慢（要降到 0.1 以下，迭代次数不够）。

下一步：把这个"逐级分位标定"写进构建（替换 `_apply_theta_last`），并把 θ 参数退化成
"目标活跃比例"（默认 85% 分位 ≈ 15% 活跃）。这样 1:1 + 阈值就同时成立。

## 四十八、纠正两个度量错误（2026-10-22）

用户指出："激活的少不一定是问题"——对，我之前错在两处：

1. **把 Jaccard 跨稀疏度直接比较**：69 个单元的码和 671 个单元的码不可比，
   同样的差异在后者的 Jaccard 里被稀释。应该用"交集占自身的比例 vs 随机期望"。
2. **"逐级取分位"其实是配额**：给每级规定活跃比例，就是 top-k 换成阈值马甲，
   违背"不要名额"的本意。真正的阈值应当按权重/结构定，活跃数随输入自然变化。

用公平度量（交集/|A|，并给出随机期望）重测 **纯 θ·(|b|+Σ|w|)、严格 1:1**：

| θ | \|A\| | 同图 | 近似 | 异图 | 近似是随机的几倍 |
|---:|---:|---|---:|---:|---:|
| 0.7 | 61 | 一致 | 0.82 | 0.30 | **50×** |
| 0.5 | 130 | 一致 | 0.89 | **0.53** | 116× |
| 0.3 | 1,198 | 一致 | 0.83 | 0.29 | 37× |

对比 top-k（671 个）：近似 0.91、异图 0.22。

**结论**：
- 纯阈值（无配额）在 1:1 下**能工作**，且同图完全一致；
- 但"近似/异图"的**比值**不如 top-k（0.82/0.30≈2.7 vs 0.91/0.22≈4.1）；
- θ=0.5 时异图高达 0.53，说明不同图共享了一大片核心单元——这是阈值模式的真问题，
  不是"码太小"的问题。

所以下一步该查的是"**为什么不同图共享核心**"，而不是继续调活跃数。

## 四十九、澄清：活跃少不是问题（2026-10-22）

用户指出：前额叶 4.1% 活跃跟真实皮层同一量级（清醒时通常 1~5%），不该当缺陷。

**接受这条，并撤回我之前的两个错误标准**：
1. "码太小（69/130 个）所以不行"——错，稀疏本身就是设计目标；
2. "异图必须 <0.3"——这是我自己定的阈值，不是用户的要求。两张不同的图共享低层特征
   本来就会重叠一部分；要判的是"**近似明显高于异图**"，不是异图必须多低。

**当前纯阈值（1:1、θ=0.5）的真实成绩**（公平度量）：

| 指标 | 结果 |
|---|---|
| 活跃 | 130 ~ 599 个（0.25% ~ 1.1%） |
| 同图两次 | **完全一致** |
| 近似（交集/|A|） | **0.89 ~ 0.91** |

## 五十一、去掉 top-k 后暴露的新问题：返回线会"灌满"前额叶（2026-10-22）

  只允许"已亮单元"的强度变化（不新增单元）。

## 五十二、学习边会制造"固定吸引子"，把不同场景并成一个（2026-10-22）

排查"灌满"的来源：

1. 先压返回线（×0.2、×0.05）——**没变化**，元凶不是返回线；
2. 再压学习边（×0.2、×0.05）——**也没变化**，|got| 仍是 12,806。

也就是学完之后，网络对两张不同的图给出了**几乎同一个码**。

**结论：29 万条学习边把网络拉进了一个固定吸引子**，输入差异被淹没；一旦进入，
在测量阶段压权重也回不来（状态已经塌了）。

所以记忆不能这样"逐拍全量学"：
- 每次转移学 1000×1000 对，800 拍就是几十万条，必然压倒感觉输入；
- 需要**限流**：每个单元的总出权重有上限、或只学"预测错误"的部分、或学到的边只做调制
（权重总和远小于该单元的门槛）。

这一条是"记忆默认开启"真正的前置条件，比返回线更根本。

## 六十一、更正：听觉区是有信号的，之前是我的测量写错了（2026-10-22）

两处低级错误（都是"视图"问题，不是架构问题）：
1. `encoder.encode()` 返回内部缓冲的**视图**，连续取两次其实指向同一块内存 → 误判"编码不变"；
2. `eng.drive()` 同理，两次取值互相覆盖 → 误判"驱动差 0.0000"。

加 `.copy()` 后重测（低音 vs 高音）：

| 层 | 相对驱动差 |
|---|---:|
| audio.L1 | 0.90 |
| audio.L2 | 0.38 |
| audio.L3 | 0.24 |
| audio.L4 | 0.20 |
| audio.L5 | 0.17 |

L5 上两种声音的**相关系数 0.66**，前 15% 赢家重合 **79%**（即 21% 的赢家会变）。

所以：听觉区**确实携带信息**，只是响应比较"相关"（0.66），不像视觉那样敏感。
用户说得对——**各区本质是同一套机制**，不需要"逐区调参"，剩下的只是灵敏度问题。

## 六十二、记忆能长、码不塌，但"空白提示"唤不起内容（2026-10-22）

加预算限流（每单元总传播权重 0.2）后重测：

| | 码大小 | A/B 重合 | 学习边 |
|---|---:|---:|---:|
| 不学习 | 1,223 / 1,378 | 0.24 | 0 |
| 学习 400 拍 | 1,255 / 1,449 | 0.27 | 58,720 |

| | 点 A 后想到 | B 独有 | 命中 |
|---|---:|---:|---:|
| 对照 | 1,223 | 879 | **0** |
| 学习 | 1,255 | 877 | **0** |

原因：预算 0.2 摊到 32 条出边，每条约 0.006；目标单元的驱动几乎为 0，怎么可能被推过门槛。

**这是一个本质取舍**：
- 要"空白提示能想起内容"，学习边就得强到能点火 → 但会连环扩散、塌成吸引子；
- 要"只做调制"，就得有别的输入先把目标带到门槛附近 → 空白提示时永远想不起来。

**所以"回忆"应该走海马体那条路**（时间线索 + 感觉内容），而不是靠前额叶的关联边硬点火。
前额叶的关联边更适合做"排序/偏向"（在有输入时帮助选出对的单元）。

## 六十四、长期化之后又出现"码合并"，而且这次是结构性的（2026-10-22）

A↔B 交替 10 轮、每段 10 拍，长期边 12,688 条。结果：

| 指标 | 结果 |
|---|---|
| 点 A 后想到 | 387 |
| **B 的独有单元** | **8**（几乎没有独有） |
| 命中 B 独有 | 0 |

`B 独有只剩 8 个`说明：**两张图的码已经合并**——长期边把 A、B 拉进了同一个吸引子。
而且这次不是"学太强"，是因为**交替出现的序列本身就是双向的**：
A→B 和 B→A 都反复出现，两条方向的边都会被写，最终互相强化成一个共同体。

**这是结构性问题，不是参数问题**：
- 要能从空白线索回忆 → 边必须强到能点火；
- 能点火 → 相互关联的几组单元会并成一个吸引子；
- 并成一个 → 就分不出"这是哪一段经历"。

真正的解法需要**模式分离**（pattern separation）：
稀疏编码 + 抑制竞争，让相似的输入映射到几乎不重叠的单元集合。
这也是海马体在生物上真正干的事（齿状回）。我们现在只有"模式补全"（pattern completion），
没有"模式分离"。

**下一步**：给长期边加"分离"约束——例如写长期边时只连**两组码里不重叠的部分**
（重叠部分本来就已经关联，不需要再加边），或者写边后做一次"去相关"。

## 六十五、只连"独有部分"也没用——合并发生在**测量时**（2026-10-22）

按上轮方案改了：长期边只连"各自独有"的单元（不连重叠部分）。10 轮后：

| 指标 | 结果 |
|---|---|
| 长期边 | 63,926 |
| A / B 码大小 | 3,226 / 3,218 |
| **B 的独有单元** | **8** |
| 点 A 后命中 B 独有 | 0 |

改了之后 B 独有仍然是 8 —— 说明**合并不是发生在"写边"时，而是发生在"测量"时**：
写进去的边一旦强到能点火，呈现 A 时它们就会把 B 的独有单元也拉亮，
最后测到的 A、B 都成了"并集"，自然就没有独有了。

所以问题不在"连哪些单元"，而在**"能不能被拉亮"**。这又回到那个死结：
- 能被拉亮 → 回忆成立，但两段经历并成一个；
- 不能被拉亮 → 分得开，但空白提示想不起来。

**生物靠"模式分离"解决：齿状回先把输入扩维、稀疏化、去相关，再存。**
我们现在是直接把感觉码存进联想边，两段本来就像，存下来必然粘在一起。

**下一步（结构性）**：在"存记忆"之前加一层扩维去相关（类似齿状回）：
把 L5 的码（约 3 千）扩成更稀疏、更不相关的一层（例如 4 倍单元、强抑制 top-k），
记忆存在那一层上。这样"像"的输入在存储层也能被拆开。

## 六十六、齿状回扩维层：运行期加单元不激活，改到构建期（2026-10-22）

`agi/dentate.py` 想用 `grow_units` 在运行期加一层扩维单元（4 倍宽、只留最强 2%），
结果新单元的活动一直是 0。

排查掉的坑：
1. `grow_units` 没扩 `_in_sum` → 加边时形状不匹配（已修）；
2. 运行期必须用 `add_edges`（不是 `connect`，后者只往构建期列表里塞）；
3. 门槛按 `thr_frac=0.5` 设，而驱动只有 ~0.4 → 全灭；降到 0.1 仍为 0。

所以问题多半在"运行期新加的单元没被纳入 top-k/计数"这条链上。
**结论：扩维层应该在建网时（`finalize` 之前）就建好**，不要运行期加。
下一轮把它挪进 `build()`，作为可选的 `spec.dentate_factor`。

## 六十七、扩维层能放电，但"回忆"仍读不到（2026-10-22）

诊断：给 5 个扩维单元加外部驱动，一拍后 act=0.4（门槛 0.1）——**放电路径是通的**
（act 一拍拍逼近，8 拍应到 1）。

`register_topk` 是在构建期登记的，`Consolidator.flush()` 里的 `rebuild_backend()` 之后
选择逻辑可能没恢复，于是所有单元都被判"未选中"。

**下一步**：查 `rebuild_backend` 是否保留 `register_topk` 的登记；或者干脆不在扩维层用
kWTA，改用"门槛 + 天然稀疏"（扩维层本来就只有 2% 超过高地门槛）。

## 六十八、扩维层：去掉名额后码大小失控（2026-10-22）

试了三种门槛（扩维层不用 kWTA，只靠门槛稀疏）：

| 门槛 | A 码大小 | B 码大小 | 两段重合 | 同图一致 |

结论：扩维层**需要名额（kWTA）才能稳住大小**，但用了名额之后"读回码"又出问题
（可能 `rebuild_backend` 之后登记丢了）。所以不是"要不要名额"的问题，
是"名额的**确定性**"问题：

- 名额要做到**同图同码**：并列时用固定优先级打破（引擎里已有 `_prio`）；
- 名额要能被 `rebuild_backend` 正确重建。

下一轮：查 `rebuild_backend` 是否保留 `register_topk`；若不保留，把登记做成可重建的。

## 六十九、修掉一个真 bug：`dentate_code` 返回的是局部下标（2026-10-22）

却被当成**全局神经元编号**去 `set_external` —— 结果点亮了完全不相干的神经元。

已修：返回 `ids[local]`（全局编号）。

|---|---:|
| A 码 | **14,569**（占 22%，太多） |
| B 码 | 1,935 |
| 两段重合 | 0.09 |

所以扩维层现在的门槛太低，活跃太多。要达到"约 2% 活跃"，要么把门槛往上调，
要么回到 kWTA（但 kWTA 之前没验证过 readback，现在这个 bug 修了之后可以再试）。

## 七十、长期记忆在扩维层上：干扰没了，但"回忆"被名额卡住（2026-10-22）

在扩维层（2% 稀疏、两段重合 0.03）上做长期化，A↔B 反复 8 轮：

| 每转移连接上限 | 长期边 | 点A命中B | 命中A | 精确率 |
|---:|---:|---:|---:|---:|
| 64 | 8,192 | 0.07 | 1.00 | 1.00 |
| 512 | 524,288 | 0.09 | 0.98 | 0.98 |
| 2,048 | 2,912,476 | **0.11** | 0.96 | 0.96 |

**把连接加多也没用**：边从 8 千涨到 291 万，B 的召回只从 7% 升到 11%，而边数涨了 350 倍。

原因：扩维层每拍只有 2% 的名额（kWTA）。点 A 时 A 的 1,300 个单元已经占满名额，
B 的单元即使被拉亮也要和 A 抢名额——**名额把回忆挡住了**。

**这是一个新的结构性认识**：
- 没有名额 → 码大小失控（5~12,744）；
- 有名额 → 回忆被名额挤掉。

所以"回忆"不能靠"同一层内的名额竞争"来读，得有一条**不占名额的读出通路**
（例如回忆时临时放宽名额，或单独一组"回忆读出"单元）。

这和之前前额叶联想遇到的是同一个问题——**竞争性读出会吃掉记忆的可见性**。

## 七十一、联想其实极强，是"名额"把它盖住了（2026-10-22）

换个量法：不数"谁被选中"，直接看**驱动**。

点 A 之后（长期边 131,072 条）：

| 单元 | 驱动均值 |
|---|---:|
| **B（被联想起来的）** | **50.09** |
| A（被点亮的） | 4.12 |
| 随机单元 | 2.58 |
| 门槛 | 0.25 |

**B 的单元被推到了门槛的 200 倍**——联想不仅存在，而且非常强。
它们没出现在"亮的名单"里，纯粹是因为 2% 的名额被 A 的 1,300 个单元占满了。

所以：
- **长期记忆本身是成立的**（A→B 的连接足够强）；
- 问题只在**读出**：竞争性名额把回忆挡在外面。

修法很清楚：回忆要有一条不跟当前感知抢名额的读出通路
（例如回忆时放宽名额，或单独一组"回忆读出"单元）。这属于读出机制，不是记忆机制。

## 七十二、"分位=配额"的正面结论：它是必要的（2026-10-22）

先量事实：**各级的"驱动/权重总量"比例差 100 倍**（平衡区 L2 中位 0.01、听觉 L5 中位 0.95）。
所以**一个全局门槛不可能同时适配**——这是结构异质性，不是调参能解决的。

再试"结构解法"：建网后把每层的入边权重整体缩放，使各级"中位驱动/总量"都归一化到 0.5，
然后用**同一个全局 θ=0.6**：

| 方案 | PFC 活跃 | 同图 | 近似 | 异图 |
|---|---:|---|---:|---:|
| 现行（每层分位标定） | 2,965 | 是 | 0.92 | **0.21** |
| 权重归一 + 全局 θ | 8,214 | 是 | 0.99 | **0.86** |

结论：**归一化之后区分度被摧毁**（异图 0.86，几乎分不开）——因为归一化把本来安静的小区
（平衡、本体）放大到饱和，它们的码不再携带信息。

所以"每层按自己的分位定门槛"不是偷懒，而是**当前架构下保住区分度的必要条件**。
它确实等价于"每层一个活跃比例"，但这正是稀疏编码该有的形式：
**每个区、每一级各自维持自己的稀疏度**，而不是全脑一个绝对门槛。

第 (3) 项按"已核查、当前架构下配额必要"结项。

## 七十三、长期化"反复出现"的判定太严：需要模糊匹配（2026-10-22）

现象：A↔B 交替 5 轮，`Consolidator` 记下 **9 种转移、每种只出现 1 次**，于是从不写入长期边。

原因：签名用的是"整组编号和"，看似稳定，但两次跑同一张图时扩维层码会
**差几个单元**（前一次的场景不同，残留状态略有差异），编号和就变了。

**修法（下一轮）**：转移的"同一性"不能用精确签名，要用**相似度匹配**：
新转移和已存的转移比较两端的交集比例（例如 >0.8 就算同一种），命中则累加计数。
这也更符合"记得的是大致同一个经历"，而不是"一字不差"。

## 七十四、要让"各区遗忘速度不同"，先得让扩维层按区分块（2026-10-22）

用户指出：遗忘不一定全脑统一，各区可能不一样，让我自己测。

先查现状——**现在还测不了**：长期边的目标区分布是

```
长期边目标区编号分布: {6: 8172}      # 6 = 伪区 "time"
```

也就是扩维层是**一个整块**（6.5 万单元全挂在 "time" 区），所有长期边都指向同一个区，
自然没法给不同区不同的遗忘速度。

**改法（下一轮）**：扩维层按感觉区**分块建**（`vision_dg`、`audio_dg`、`touch_dg`…），
每块继承自己区的编号。这样：
1. 长期边天然带上"这条记忆属于哪个区"；
2. 遗忘速度可以按区分开（例如视觉记忆稳、触觉记忆快）；
3. 也方便对比"统一衰减"和"分区衰减"哪个更好。

这不增加机制，只是把已有的一层**按区拆开**，和"各区本质一样、只是参数不同"是一致的。

## 七十五、扩维层按区分块了，但视觉块太大导致"几乎只有视觉记忆"（2026-10-22）

已改：扩维层改成每个感觉区各建一块（`vision 61,440 / audio 2,560 / touch 400 / proprio 720 / balance 200`）。

但长期边的目标区仍然是 `{vision: 8192, 其他: 0}`，原因是**块大小差了 240 倍**：
每块都只留 2% → 视觉 ~1,229 个活跃，听觉 51、触觉 8、本体 14、平衡 4。
整份码 94% 是视觉，随机抽 64 个自然几乎全是视觉。

这不是 bug，是"块大小按输入规模定"的必然结果。要比较各区的遗忘速度，有两条路：
1. **每个区给同样的块大小**（比如都 4,096），让各区都有足够单元参与记忆；
2. **按区分层抽样**（每个区各抽固定数量），保证每条记忆都覆盖到各区。

我倾向第 2 条：不改变"输入大→表征多"的事实，只是在"写长期记忆"时保证各区都有代表。
下一轮实现并测"各区不同遗忘速度"。

## 七十六、扩维层的代价：默认开不了（2026-10-22）

## 七十八、严重问题：长期化会把扩维层"锁死"（2026-10-22）

试过的修法：给每个源的出边加总权重上限（budget=0.5）——**无效**。
说明问题不只是"边太强"，更可能是"新增边让 `rebuild_backend` 后的驱动/门槛关系变了"。

（17/17、0 issues、地基符合、整拍 12.4 ms / p95 14.4）。
长期化仍可手动开启（实验用），但在修好之前**不能默认开**。

## 七十九、锁死的真因：组号撞车（2026-10-22）

上一轮"长期化把扩维层锁死"，真因不是"边太强"，而是**组号冲突**：

- 扩维层的输入边用**组 66**；
- 回忆镜像边用了 `group + 1` = **组 66**；
- `flush` 里清理镜像边时 `drop_edges(group==66)`，把扩维层的 13 万条输入边一起删了
  （实测 130,561 → 47,442），于是扩维层拿不到输入 → 全灭。

修法：镜像边改用**组 67**（`group + 2`）。修完后连续 6 次运行扩维活跃稳定 652，
组 66 保持 130,561 条不丢。

`long_term` 已恢复默认开启，全套检查：17/17、0 issues、地基符合、
整拍 12.21 ms（p95 12.83）、狗 0.269 站住、规则表可用。

**教训**：组号是全局共享的，新增一种边就相当于"占用一个组号"——
以后加新边组要先查已用组号，不能拍脑袋用 `group+1`。

## 八十一、多段顺序失败的真因：模糊匹配太松，把不同转移并成了一种（2026-10-22）

诊断（A→B→C→B 跑 10 轮）：

```
过渡数 29，次数 [1,1,1,1,2,2,...,35,99,142]
长期边 435,299
A->B 52.4   A->C 53.4   随机 0.9
```

- 29 个"转移"里，**有一个出现了 142 次**——显然不是同一种经历（序列里每轮只有 4 个转移）；
- 说明 `match=0.8` 的相似度判据把**不同的转移并成了一种**，于是写进去的长期边是"混在一起"的；
- 结果点 A 时 B 和 C 被推得一样高（52.4 vs 53.4），分不出先后。

**修法**：把转移的判定改严（例如要求两端相似度都 >0.9，或同时比较两端的"规模相近"），
并给每个模板记录真实的码，写边时用它而不是最新一次的码。
这属于"记忆粒度"问题，不是传播问题——之前以为是扩散，是误判。

## 八十二、"多段顺序"仍失败：三种猜测都排除了（2026-10-22）

依次试过并排除：

| 猜测 | 改动 | 结果 |
|---|---|---|
| 模板把不同转移并成一种 | `match` 0.8→0.9 + 规模相近判据 | 模板 29→23、最大次数 142→5（**修好了**），但 A→B 仍 ≈ A→C |
| 传播扩散 | 只走 1 拍再看 | 仍 ≈ 相等 |
| 边太密（cap 512 一次写 26 万条） | cap 512→32 | 仍失败 |

诊断数据（cap=512、n=1）：A→B 358.3、A→C 363.9、随机 6.5——
**两者都远高于随机，说明 A 确实"想起了东西"，但分不清想起的是 B 还是 C。**

下一步要做的不是调参，而是**直接检查边**：A 的单元是否真有指向"B 独有单元"的边，
以及这些边的权重与指向"C 独有单元"的边相比如何。这一步能把"记忆内容错"和"读出被平均"分开。

## 八十三、噪声鲁棒性差，问题出在感觉层不在前额叶（2026-10-22）

题库最后一题（3% 噪声）一直不过，量化了一下：

| 噪声 | L5 码重合 | PFC 码重合 |
|---:|---:|---:|
| 0.5% | — | 0.62 |
| 1% | **0.58** | 0.51 |
| 3% | 0.51 | 0.43 |
| 8% | — | 0.40 |

**结论：不稳定从 L5 就开始了**（1% 噪声只剩 0.58），不是前额叶放大出来的。
而且噪声越大码越"大"（3.6k → 5.1k），说明噪声是在**增加活动**，不是打乱原有活动。

可能的原因：温度计编码里，像素值落在档位边界附近时，1% 的扰动就会翻档；
视觉通道数多（6,144 个 L1 单元），翻档的绝对数量就大。

**可试的修法**（下一轮）：
1. 降低温度计档位敏感度（每档更多冗余单元，翻档影响被摊薄）；
2. 感觉层加短时整合（同一图连续几拍的活动做平滑），噪声是每拍独立的，平均后会降；
3. 接受它——如果这属于"编码本身的抖动"，那就该在题库里把阈值定在合理位置，
   而不是硬要求 0.5。

## 八十四、注视任务：水平方向已经"天生对"，垂直方向不行（2026-10-22）

扫 5×5 个球位置，看运动区 12 条肌肉的输出与球偏移的相关：

| 方向 | 最好的肌肉 | 相关 |
|---|---|---:|
| 水平（x） | 2 | **0.79** |
| 垂直（y） | 9 | **0.19** |

也就是说：**出生随机连接里，水平方向已经天然对齐了**（球偏右，肌肉 2 的输出就变大），
垂直方向几乎没有信息（12 条肌肉的相关都在 0.19 左右）。

所以注视任务 0/6 的原因是：**横向能追，纵向追不动**。

这是很具体的一个结论：
- 说明"视觉→运动"这条通路**不是完全随机的**，空间结构让它天然带上了水平方向信息；
- 垂直方向要么靠学习补上，要么说明视觉编码里垂直信息本来就弱（值得单独查）。

下一步二选一：
1. 先测"只做水平注视"能不能过——验证通路本身是通的；
2. 直接查垂直方向为什么弱（是编码的问题，还是运动区的问题）。

## 八十五、注视任务：接口改对了，能力还很弱（2026-10-22）

关键修复：**肌肉力度是 0..1 的非负值**（静息为 0），不能直接当有符号的注视位移。
我原来写 `2f-1`，静息时输出 -1，注视窗一直往角落跑（实测轨迹：每拍 -0.25，最后钉在 (-1,-1)）。

改成**拮抗对**（一条推、一条拉，差值才是方向）：`a = f[2]-f[3]`、`b = f[9]-f[10]`。

修完后的成绩：

| 指标 | 结果 |

## 九十二、"能走"没验证成功：简单节律不产生位移（2026-10-22）

## 一百零四、病根：力度细胞全部饱和，任何上游差异都传不到力度（2026-10-22）

**末拍 120 个力度细胞全部激活**（每块肌肉 10 档全亮）。

## 一百二十、读懂了：`inh` 是"死端口"——只有进、没有出（2026-10-22）

`build.py` 第 497–523 行的门控：

```
inh(16)   ← 非运动前额叶（16×6，权重0.1~0.2）
          ← touch L5（16×4，权重0.1~0.2）

force(120) → inh（每块肌肉 10 档各连 2 个，权重1.1，组名 MOTOR_BLOCK）
```

**没有任何 `inh → 某处` 的边。**

也就是说：`inh` 只被"填"，从不"倒出来"——它是个**死端口**。
所以上一轮把墙敏感单元接到 `inh` 上完全没反应，是必然的。

**正确的接法**（很小）：
```

```
即：让"看到墙"直接压住力度细胞，而不是经过 inh。
这需要引擎支持负权，或者利用 `inh=True` 块的输出符号。

下一步：先查引擎里"负权/抑制块"到底怎么表达，再接线。

## 一百二十四、找到真 bug：`connect(dst, src, w)` 参数顺序（2026-10-22）

`engine.connect` 的签名是：

## 但行为还是不变——因为位移主要来自"滑"，不是"蹬"

| wall_inh | gain | 无墙 | 有墙 | 比值 |
|---|---|---:|---:|---:|

抑制边确实在算（力度会降），但**位移不变**——说明这 0.29 米主要不是"蹬"出来的，
而是机身姿态造成的**滑动**。压住力度并不能让它停下。

**结论**：避障这道题用"位移比值"来判，测到的其实是滑动，不是"停不停"。
要么换判据（比如"有墙时腿不摆/力度下降"），要么先解决"位移来自滑动"这个更根本的问题。
