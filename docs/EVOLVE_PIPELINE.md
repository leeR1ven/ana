# 演化流水线：融合 + 技能不遗忘

## 一、模型融合（照老库的做法）

老库的"融合"不是神经网络权重合并，而是**对"出生参数"按位平均**：

```
融合后的参数 = (父 A 的参数 + 父 B 的参数) / 2       # 逐项
变异后的参数 = 融合参数 + 小步随机抖动
```

ana 的出生参数：

| 参数 | 含义 | 融合方式 |
|---|---|---|
| `k_near` | 感受野大小 | 取整平均 |
| `region_links` | 区与区连接数 | 取整平均 |
| `w_lo` / `w_hi` | 出生权重范围 | 浮点平均 |
| `n_time` | 时间环长度 | 取整平均 |
| `seed` | 随机种子（决定具体连线） | **不融合**，每次重新取 |

注意：`seed` 不能平均——它决定具体连了哪些边。融合的是"结构参数"，不是"连了哪几条边"。
所以融合后一定伴随一次变异（换 seed + 各参数小抖动），否则会得到和父代一样的结构。

## 二、技能清单（不遗忘）

维护一份 **skill ledger**，只增不减：

```
ledger = {
  "走":     {"判据": "位移>0.05 且不摔", "已获得": True, "第几代": 3},
  "朝红球走": {...}, "转向": {...}, ...
}
```

### 选候选的规则

1. 候选模型必须**通过 ledger 里所有"已获得"的技能**；
2. 只要有一项退化 → **不保留**（哪怕新技能分更高）；
3. 通过某项新技能 → **加入 ledger**，并记录代数；
4. 每代输出：`代 N | 技能 k/m | 新技能: xxx | 最好位移 x.xx`。

这样保证：**技能清单只增不减，留下的模型会的技能越来越多**。

### 为什么必须这样做

如果没有这条规则，搜索会"捡了芝麻丢西瓜"：
为了走得更远，可能把"站住"练没了——这就是灾难性遗忘。
把"老技能也要过"写进筛选规则，等于把"不遗忘"变成了硬约束。

## 三、一条命令跑完

```
python -m agi.dog_evolve --gens 5 --pop 300
```

流程：

```
第 1 代：随机生成 300 个 → 跑全部技能题 → 按"技能数 + 未获得技能的最好成绩"排序
第 2..N 代：
    取前 2 名 → 融合 → 变异 → 生成 300 个后代
    全部跑技能题（含老技能）
    过滤：老技能有退化的直接淘汰
    更新 ledger（谁过了新技能就记上）
输出：每代技能数、最好成绩、最后模型存盘
```

## 四、上服务器前的验收标准

- 本机能跑通 3 代、技能数单调不减；
- 单模型评分时间稳定（当前 4~8 秒，含 mujoco 任务会更慢）；
- 结果可复现（同 seed 同结果）。

## 专科状元 + 综合状元 一起繁育（2026-10-22）

用户要求：既要"某一科突出"的，也要"综合好"的，两者一起融合。

实现（`agi/dog_evolve.py`）：

- `best` = 综合状元（技能数优先、其次指标和）；
- `specials[技能]` = 该技能的**指标最高**的模型（哪怕它别的技能都不行）；
- 每代孩子 = `变异(best)` + 若干 `变异(specials 各项)` + `变异(融合(best, 某科状元))`；
- 结果：专科的"偏才"不会被综合筛选淘汰掉，还能把它的长处融进综合模型。

首次运行（2 代，从 walk_best.json 起步）：

```
第 1 代：技能 1/5 ['walk1']
第 2 代：技能 1/5 ['walk1']
```

清单已能记录"第几代学会哪项"，`walk1`（走 3 厘米）是第一个被记上的技能。
