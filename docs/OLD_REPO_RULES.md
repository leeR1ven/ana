# 老库的实测规矩（chain-neuron-architecture / local3d-similarity）

这些不是"设计原则"，是那边**每条都有实测依据**的结论。摘在这里，作为改 ana 之前的必读清单。
原文件：`refs/chain-neuron-architecture/README.md` 第二节、`验收标准.md` 第三节。

| # | 规矩 | 那边的依据 |
|---|---|---|
| 1 | 就近只看 (y,z)，层间 x 差不参与 | 否则每层只看到上一层最靠边一排 |
| 2 | **深层感受野 ≤ 上一层的 1/8** | 视觉第 3 层可分：整层 0/12 → 1/4 时 2/12 → **1/8 时 12/12** |
| 3 | 不能窄到"只读一条通道"（要"主 + 对照"） | 否则第 2 层从 11/12 掉到 1/12 |
| 4 | 门槛/带宽按**该神经元自己拿到的信号**定 | 固定常数会在"整层死/整层饱和"之间跳 |
| 5 | **中继和前额叶那一层要更松**（门槛 ≈ 0.30×中位驱动） | 送达前额叶从 7/48 变 48/48 |
| 6 | 回程只当调制（边数 ≤ 前向一半） | 回程占入边 22/30 时前向被压死 |
| 7 | 整体阈值只许微调（相对增益 ±0.05） | 放到 ±0.5 会顶到上限，深层必死 |
| 8 | 各层必须在分级区间 | 饱和传不出变化；死什么都没传 |
| 9 | 门槛不许有固定下限（如 0.02） | 它让下降链每过一级固定损失，力度低端被压缩 |
| 10 | **链上每级一对一（专用线），只有前额叶汇聚** | 随机输入相似性：第2层 0.44 → 第4层 0.11 → 前额叶 0.0；改一对一后四区送额叶 100% |
| 11 | 增神经元：L2–L5 都能加，越深越好 | 中等规模 L2 0.566 / L3 0.543 / L4 0.532 / L5 **0.511** |
| 12 | **常亮/常灭不往前额叶送** | 输入层永远一半亮，但不带"是哪一个输入"；按跨输入 std 判定 |
| 13 | 回程门槛必须可达（≤ 入边权重和） | 写 2.0×权重和时 act≤1 永远打不开 |
| 14 | 回程要**随机铺开**看前额叶，不能只取最近 | 只取最近会变成看局部小簇（20% 前额叶就打开） |
| 15 | 每层中继从**本层** x 出发向额叶递进 | 从输入层 x 出发会让 L3/L4 往身后的中继送 |
| 16 | **稳定 ID**：删除只改 alive、不移位 | 加神经元要补中继和额叶接收端 |

## 对 ana 的对照（哪些已经在做、哪些可能踩了）

| # | ana 现状 | 判断 |
|---|---|---|
| 2 | 视觉 L1 的感受野按 `k_near` 定，深层按网格缩小 | 需核：是否 ≤ 1/8 |
| 4 | 门槛按"该层驱动的分位"定（q=0.70） | **按层**而非按神经元；小区曾整层饱和，可能就是这个原因 |
| 5 | 中继/前额叶门槛由同一套标定 | 需核：是否够松（0.30×中位驱动） |
| 6 | 回程（ret 路径）边数未专门限制 | 需核 |
| 10 | 中继 r1→r2 是 1:1，前额叶汇聚 | ✅ 已符合 |
| 12 | **听觉/触觉/本体/平衡输入是恒定值 → 整层常亮** | ❌ **正踩这条**：我们实测"静音也让听觉 L5 全亮"，正是"常亮"被送进前额叶 |
| 16 | 引擎有稳定 ID（不删不移位） | ✅ 已符合 |

## 最有价值的一条

**第 12 条**直接解释了我们查了很久的现象：听觉/触觉输入恒定时，温度计编码是"半亮"的固定图案，
传到 L5 就整层饱和。那边早就给出了判据（按跨输入 std 判定"常亮"）和做法（不往前额叶送）。
我们不该在阈值上反复调，而应该**把常亮的那部分从送往前额叶的通路里摘掉**。

## 老库"测试→融合→再生成"的确切参数（`train_loop.py`）

```python
def main(gens=3, pop=4, keep=2)
```

- **代数 3、每代 4 个、保留 2 个**（精英 + 变异体）；
- 第 1 代：4 个随机出生参数；
- 之后每代：**上一代最优原样进下一代**，其余是它的变异体；
- 变异：`k_near ±2`、`layer_ratio ×0.85~1.15`；
- 打分：**同一套固定题库**（只改一个通道/位置，看深层和前额叶变没变），按通过率。

README 的原话（第 89 行）：

> 随机出生参数 → 同一套固定题库打分 → 选优 → **精英保留 + 在最优者身上小步变异** → 再生成。

### 对 ana 的启示

1. 我们 `evolve.py` 的结构**和老库一致**（精英保留 + 变异 + 融合），没跑偏；
2. 老库自己是 **4 个/代**，不是上千——上千是"扩大规模"的做法，不是必须；
3. 真正决定成败的是**题库的分辨率**（能不能把 4 个模型排出高低），
   这也是为什么我们换成 140 个小测之后，分数才从"清一色 0.80"变成 0.31~0.91；
4. 扩容时要同时扩两件事：**每代模型数**（pop）和**小测数**，只扩一个没用。
